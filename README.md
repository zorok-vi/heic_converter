# HEIC → JPEG / PNG

Локальное приложение с русским веб-интерфейсом. Выберите HEIC/HEIF, настройте
JPEG или PNG, нажмите «Конвертировать», скачайте отдельные изображения или ZIP.
Установка Node.js и получение зависимостей выполняются один раз. После подготовки
приложение работает без интернета, регистрации, облака и внешнего сервера.

**[Скачать приложение ZIP](https://github.com/zorok-vi/heic_converter/archive/refs/heads/main.zip)** —
в архив включена готовая сборка `dist`, Node.js устанавливается отдельно.
**[Пошаговая инструкция для macOS](MACOS.md)**: скачивание, установка Node.js и запуск.

## Быстрый запуск готовой поставки

1. Распакуйте **весь архив**, не запускайте файлы внутри ZIP.
2. Установите **Node.js 24.15.0 или новее в ветке 24** с https://nodejs.org/.
   Версии 22, 25 и 26 не входят в заявленный диапазон этого проекта.
3. В архив уже включён `dist`. На Windows откройте **start.bat**. На macOS —
   **start.command**. На Linux выполните **./start.sh**.
4. После начала прослушивания откроется http://127.0.0.1:8080.
   Если браузер не открылся, скопируйте этот адрес из окна запуска.
5. Для остановки нажмите **Ctrl+C в окне запуска**. Вкладку можно закрыть отдельно.

При скачивании через GitHub папка называется `heic_converter-main`. Готовый `dist`
хранится в репозитории намеренно, чтобы скачанный ZIP запускался без npm ci и сборки.

При готовом `dist` серверу не нужны `node_modules`, npm или сеть. Он написан
только на встроенных модулях Node.js. Сценарий без `node_modules` проверен на Linux.
Если права выполнения shell-скриптов не сохранились при распаковке:
`chmod +x setup.sh start.sh start.command`. Запускайте приложение обычным
пользователем: администратор, открытие портов роутера и изменение firewall не нужны.

Основная целевая платформа — Windows 10/11 с актуальным Chrome/Edge. Это цель,
а не заявление о проведённой Windows-приёмке. Фактическая матрица ниже.

## Однократная подготовка из исходников

Если `dist` отсутствует, вы изменили исходники или хотите самостоятельно
воспроизвести сборку:

```bat
setup.bat
```

На macOS/Linux:

```sh
./setup.sh
```

Скрипты проверяют Node.js/npm, выполняют `npm ci`, затем `npm run build`.
**Для первоначального получения зависимостей нужен интернет**, если они не
подготовлены заранее в локальном npm-кэше. Node.js устанавливается пользователем
явно; скрипты не скачивают установщик Node и не запускают удалённые shell-команды.
При ошибке подготовка прекращается с ненулевым кодом и сообщением. На Windows
окно ожидает нажатия клавиши; интерактивный setup.sh также даёт прочитать ошибку.

Диапазон `>=24.15.0 <25` выбран с учётом Vite 8, Vitest 5, ESLint 10 и jsdom 30.
Проверена Node.js 24.19.0 с npm 11.9.0. Точные зависимости зафиксированы lock-файлом.

## Повседневная работа

Обычные стартовые скрипты ничего не устанавливают, не обновляют и не собирают.
Они определяют папку приложения по своему расположению. `file://index.html`
не поддерживается: Worker и локальные модули загружаются через HTTP.

Из терминала в папке приложения:

```sh
npm start
npm start -- --port 8081
```

Смена порта без npm:

```sh
node scripts/server.mjs --port 8081
./start.sh --port 8081
```

Допустимы порты 1024–65535. Привязку изменить нельзя — только `127.0.0.1`.
Если порт занят, запуск завершается с понятной ошибкой: чужой процесс не
останавливается, чужой адрес не открывается в браузере. Повторите с другим портом.

Для ручного открытия браузера предусмотрен `--no-open`:
`node scripts/server.mjs --no-open`. Окно запуска остаётся работающим до Ctrl+C.
Закрытие вкладки **не останавливает сервер**. Перезагрузка вкладки очищает список.
Приложение может показать браузерное предупреждение при наличии результатов;
браузер сам решает, показывать ли его. Независимая системная фоновая служба
не создаётся. Закрытие окна консоли не заменяет документированную остановку Ctrl+C.

## Что реализовано

- Выбор нескольких файлов и drag-and-drop. MIME может быть пустым или общим;
  расширения `.heic`/`.heif` проверяются без учёта регистра.
- Проверка контейнера ISO BMFF `ftyp` и HEVC-брендов `heic`/`heix`, включая
  совместимые бренды. AVIF, generic HEIF неизвестного кодека и последовательности
  отклоняются. Окончательная проверка — реальное декодирование.
- JPEG, качество 10–100% (по умолчанию 90%), либо PNG без фиктивного ползунка качества.
- Один файл одновременно. Для каждого задания — новый Worker; тяжёлый декодер
  загружается только при начале обработки. До этого показывается «Подготовка конвертера…».
- Состояния queued/processing/done/error/cancelled, общий прогресс по заданиям,
  отдельные ошибки, отмена, тайм-аут, повторы, очистка и удаление отдельных файлов.
- Параметры и состав партии фиксируются при старте. Готовые файлы не повторяются
  при нажатии «Повторить ошибки и отменённые». Для явной полной переработки есть
  «Конвертировать всё заново». Параметры старых результатов подписаны отдельно.
- Дубли по `name + size + lastModified` пропускаются с сообщением. Это эвристика,
  а не сравнение содержимого. Одинаковые имена при разных характеристиках разрешены.
- Предпросмотр только после конвертации, индивидуальное скачивание и
  `converted-images.zip` только из успешных результатов. Коллизии имён получают
  суффиксы `(2)`, `(3)`; русские имена сохраняются, опасные сегменты путей очищаются.
- У ZIP отдельный статус, повторный запуск блокируется; сборку можно отменить.
  JPEG/PNG уже сжаты, поэтому ZIP использует STORE без повторного сжатия.

Папку сохранения определяют настройки браузера и выбор пользователя. Оригиналы
не изменяются, не удаляются и не перезаписываются приложением. Очистка интерфейса
не удаляет скачанные файлы с диска. Размер результата может превышать исходный.

## Приватность и локальный HTTP

Сервер нужен только для раздачи интерфейса, JS и Worker из `dist`. Фотографии,
имена и результаты ему не передаются. Нет upload/conversion API, записи фотографий
на серверный диск, внешних шрифтов, CDN, аналитики, телеметрии, проверки обновлений
или Service Worker. Файлы и Blob находятся в памяти вкладки; приложение не
записывает их в localStorage, IndexedDB, Cache Storage и серверные временные файлы.
Браузер может самостоятельно использовать внутренние механизмы хранения Blob;
гарантированное физическое стирание RAM/подкачки средствами JavaScript не обещается.

Сервер раздаёт только файлы из build-списка `dist/static-files.json`, проверяет
нормализованный и реальный путь, отклоняет symlink за пределы `dist`, не показывает
каталоги и не использует SPA-fallback для отсутствующих Worker/WASM. Разрешены
GET/HEAD, Host должен точно совпадать с `127.0.0.1:порт`. CORS `*` не включён.
Присутствуют CSP, nosniff, no-referrer и Cache-Control: no-store. Исходники,
`node_modules`, `.env`, лицензионные архивы и остальной репозиторий не раздаются.

CSP не разрешает `unsafe-eval`, внешние источники или WASM-eval. `worker-src 'self'
blob:` нужен для вложенного Worker декодера. `img-src` разрешает локальные и Blob
изображения; `data:` используется для пустой встроенной favicon. `connect-src`
ограничен своим origin. Во внешние сервисы никаких fallback нет.

Все необходимые runtime-ресурсы включены в `dist`: приложение, адаптер, Worker,
декодер (~3,2 МБ JS/asm.js), ZIP core и CSS. Отдельный WASM не используется.
Интернет нужен для первоначального получения зависимостей, а не для конвертации.

## Декодер, ориентация, метаданные

Используется **heic-to 1.6.7**, внутри **libheif 1.23.7 / libde265 1.0.16**.
Версии подтверждены заголовком upstream `src/lib/libheif-without-unsafe-eval.js`.
Кандидат `heic-to/next` проверен в production Worker: его embind вызвал `new Function`
и был заблокирован строгой CSP. Вместо ослабления политики выбран **heic-to/csp**:
только его документированный bitmap API, проверенный в настоящем Worker.
Ветка bitmap не обращается к `document`; затем адаптер кодирует через OffscreenCanvas.
Импорт JPEG/PNG напрямую из csp в Worker не используется, поскольку эта ветка
upstream обращается к DOM canvas. Библиотека изолирована в `src/conversion/adapter.ts`.

libheif применяет контейнерные повороты/зеркальность; приложение не поворачивает
bitmap второй раз. Проверены синтетические ориентации 6 и 2, размеры и контрольные
цветовые области. Произвольные EXIF-only или противоречивые контейнерные/EXIF
ориентации на всех моделях камер не проверены. Разрешение не уменьшается.
Для JPEG alpha компонуется на белый фон; PNG сохраняет полученную от декодера alpha.

Upstream выбирает изображение с `is_primary()`, иначе — первое доступное.
Проверен контейнер, где основное изображение второе. Если primary отсутствует,
поведение fallback ограничено первым доступным: нет обещания поддержки всех
вариантов HEIF. Depth/gain maps не экспортируются отдельно. Live Photo, видео,
анимация, все кадры серий и AVIF не входят в версию 1.

Сохранение исходных HDR, глубины цвета, ICC-профиля и точного цветопереноса
не гарантируется. Это стандартный браузерный RGBA/canvas-процесс, а не архивный
конвертер с управлением цветом. Утверждение «без потери качества» не применяется
ни к PNG-цепочке целиком, ни к JPEG с качеством 100%.

Изображение кодируется из пикселей: исходные EXIF/XMP/IPTC/GPS не копируются.
На фикстуре с реальными EXIF Artist/Make/GPS и XMP проверено отсутствие исходных
данных, APP1 JPEG и EXIF/text PNG. Кодировщик может создавать служебные поля
(например JFIF); обещания отсутствия вообще любых метаданных нет. Текст и лица
на самой фотографии остаются видимыми.

## Лимиты и память

Конфигурация — `src/config.ts`:

| Параметр | Значение |
|---|---:|
| Файлов в очереди | 20 |
| Один оригинал | 30 МиБ |
| Все оригиналы | 150 МиБ |
| Разрешение | 50 Мп |
| Хранимые результаты | 200 МиБ |
| Время на файл | 120 секунд |

Это продуктовые ограничения, **не гарантия безопасной обработки на любом ПК**.
**heic-to не предоставляет проверку размеров до декодирования** через публичный
bitmap API. Лимит пикселей проверяется после создания bitmap, до canvas-кодирования.
Значит, слишком большое или вредоносное изображение способно вызвать пик памяти
до этой проверки. Размер сжатого оригинала не защищает от этого. Партия предельного
размера и фотографии 50 Мп на разных ПК не испытаны.

50 Мп требуют около 200 МБ только на один RGBA-буфер. Во время работы возможны
несколько копий: декодер, structured clone, ImageBitmap, canvas и кодирование Blob.
ZIP также собирается в Blob и требует дополнительной памяти; потоковые записи
внутри ZIP не означают постоянного потребления RAM. Предпросмотры браузера тоже
могут декодировать результаты. На слабом ПК используйте меньшие партии.

При превышении 200 МиБ последний результат отбрасывается, готовые сохраняются,
остальные задания остаются в очереди. Скачайте готовое, удалите ненужный файл
из списка либо нажмите «Убрать результат», затем «Конвертировать». Убранный результат
помечается отменённым и не обрабатывается этой кнопкой повторно; его оригинал
остаётся доступен для явного повтора отменённых или полной переработки.

По отмене/тайм-ауту Worker завершается, следующий файл получает новый Worker.
При отмене готовые результаты сохраняются. Очистка завершает обработку и удаляет
ссылки на оригиналы/результаты. Object URL отзываются, bitmap закрывается, canvas
уменьшается в finally; вложенные Worker завершаются вместе с родителем. Скачанный
ZIP имеет временный Object URL до 60 секунд, также отзываемый при очистке.
Проверка размера готового Blob не предотвращает временный пик при его создании.

## Команды разработки и проверки

```sh
npm ci
npm run dev
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
npm start
npm start -- --port 8081
npm run test:e2e
```

`dev` и `preview` явно ограничены loopback. `preview` — только проверка сборки;
`npm start` использует отдельный штатный сервер без установки/сборки.
`npm test` выполняется однократно: Vitest (логика/UI/ZIP) и Node test (сервер/скрипты).
Проверки Unix shell и xdg-open пропускаются на неподходящих ОС; на Windows
невозможность создать symlink явно отмечается в диагностике. Пропуск не считается
успешной Windows-проверкой стартовых скриптов.
E2E требует предварительный `npm run build`, запускает готовый `dist` через тот же
сервер и start.sh на Linux. Зависимость Playwright уже в lock-файле; отдельно
установите тестовый браузер `npx playwright install chromium` при наличии интернета.
Эта команда нужна только разработчику для тестов, не обычному пользователю.
Системный Chromium можно указать: `CHROMIUM_PATH=/путь/к/chromium npm run test:e2e`.
На PowerShell: `$env:CHROMIUM_PATH='C:\path\chrome.exe'; npm run test:e2e`.

E2E использует Chrome DevTools Protocol для контроля вложенных Worker, поэтому
эта тестовая конфигурация ориентирована на Chromium. Открываемый для тестов
служебный CDP-порт ограничен loopback, выбирается автоматически и закрывается
с тестовым браузером; в обычных start-скриптах его нет.

- Отдельные ошибки, повреждённый HEIC, переименованный PNG, русские и совпадающие

- Сервер: Host, методы, MIME/CSP, traversal/URL-кодирование/symlink, занятый порт,
  отсутствие Node/npm/dist, неподдерживаемая версия, повторный запуск после SIGINT,
  путь с пробелами/кириллицей и работа без node_modules.
- Офлайн-сценарий: новый контекст и пустой кэш, только точный loopback-origin
  разрешён для страницы; CDP отдельно блокирует внешние HTTP(S) и регистрирует
  сеть Worker **до их исполнения**, включая вложенный Worker. Первый декодер,
  JPEG/PNG, скачивание, ZIP, очистка и повтор прошли. Внешних попыток и запросов
  с фотографиями/именами нет. Это контроль трафика приложения, не обещание
  отсутствия системного фонового трафика браузера или ОС.

**Не проверены:** Windows 10/11, start.bat/setup.bat на Windows, Edge, macOS,
Safari, Firefox, физическое отключение сетевого адаптера и предельная реальная
партия 150/200 МиБ. Windows-скрипты подготовлены и просмотрены, но это не испытание
на Windows. Эмуляция узкого экрана проверяет вёрстку, а не доступ с телефона.
Сервер намеренно недоступен с телефона и других компьютеров сети.

## Как самостоятельно проверить сеть и loopback

1. Запустите готовую сборку. В DevTools → Network очистите список, отключите кэш,
   затем впервые конвертируйте файл. Запросы должны содержать только локальные
   HTML/JS/CSS, без upload POST, фотографий и имён в URL.
2. Отключите внешний интернет, сохранив loopback. В новом профиле браузера откройте
   приложение, выполните JPEG/PNG и скачайте ZIP. Не используйте глобальный режим
   DevTools Offline, если он блокирует также локальную загрузку интерфейса.
3. Windows PowerShell: `Get-NetTCPConnection -LocalPort 8080 -State Listen`.
   LocalAddress должен быть `127.0.0.1`. Linux: `ss -ltnp 'sport = :8080'`.
   macOS: `lsof -nP -iTCP:8080 -sTCP:LISTEN`. Не должно быть `0.0.0.0` или `[::]`.
4. Нажмите Ctrl+C и убедитесь, что порт освобождён. Затем запустите снова.

## Типовые ошибки

| Сообщение / ситуация | Что сделать |
|---|---|
| Node.js не найден | Установить Node 24.15+ в ветке 24, заново открыть терминал |
| Версия не поддерживается | Использовать диапазон из package.json, а не случайную старую Node |
| Нет npm | Установить Node с компонентом npm; для готового dist достаточно Node |
| Нет/повреждён dist | Выполнить setup или npm ci и npm run build |
| Порт занят | npm start -- --port 8081 |
| Браузер не открылся | Оставить сервер работающим и вручную открыть напечатанный URL |
| HEIF не поддерживается | Нужен статичный HEVC HEIC с heic/heix; AVIF/видео не поддерживаются |
| Тайм-аут / ошибка памяти | Меньшая партия, закрыть лишние вкладки, удалить результаты, повторить |
| Пауза по бюджету | Скачать готовое, убрать результаты или задания, продолжить очередь |
| Список исчез после обновления | Сеанс хранится только в памяти; добавить оригиналы снова |

## Структура и лицензии
