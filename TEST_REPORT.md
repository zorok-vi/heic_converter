# Отчёт о проверке

Дата: 30 октября 2026 года. Среда: Linux 6.18.57, Debian,
Node.js 24.19.0, npm 11.9.0, Chromium 154.0.8037.57, Playwright 1.64.1.
Windows и macOS в этой среде отсутствуют.

## Команды

```sh
NPM_CONFIG_CACHE="$PWD/work/npm-cache" ./setup.sh
npm run typecheck
npm run build
npm run lint
npm test
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
sha256sum -c vendor-sources/SHA256SUMS
```

setup.sh фактически выполнил npm ci и production build; установлен lock-набор
из 236 пакетов для Linux. Вспомогательный путь npm-кэша относится к среде разработки,
не является требованием установки у пользователя. Последний полный вывод проверок
включён в TEST_RESULTS.txt.

## Что проверялось фактически

**Настоящий декодер.** HEIC с HEVC → настоящие JPEG/PNG: MIME Worker-ответов,
сигнатуры, открытие изображений, размеры и контрольные цветовые области. Исходные
изображения созданы для проекта; лицензия и происхождение описаны рядом с фикстурами.
PNG под видом HEIC отклоняется, повреждённый HEIC получает ошибку, следующий
корректный файл продолжает обрабатываться.

**Ориентация/alpha/primary.** Проверены портрет 96 × 160 (ориентация 6), отражение
160 × 96 (ориентация 2), отсутствие двойного поворота, прозрачная половина PNG,
белая половина JPEG и контейнер с основным изображением на второй позиции.
Качество JPEG 10% и 100% даёт разные декодируемые результаты на шумовой фикстуре;
общая монотонность размеров для всех фотографий и браузеров не предполагается.

**Метаданные.** На исходнике действительно есть EXIF Artist/Make, GPS IFD
с тегами 1/2/3/4 и XMP-маркер. Проверено отсутствие исходных маркеров и APP1 JPEG,
EXIF/text-чанков PNG в результатах. Служебные метаданные кодировщика не запрещаются.

**Очередь.** Реальные отмена/повтор/очистка/новая конвертация и сброс списка при
перезагрузке. Unit-тесты отдельно проверяют последовательность, фиксацию настроек,
повторы только нужных состояний, тайм-аут, завершение Worker, старые runId/jobId,
освобождение URL, все числовые лимиты, паузу бюджета и возобновление после удаления.
Моки используются только для контролируемых состояний, а не вместо декодера.

**Скачивание/ZIP.** Индивидуальные реальные скачивания, читаемые русские имена,
коллизии `(2)`, только успешные записи архива. ZIP открыт независимым читающим API,
байты записей совпали с индивидуальными скачиваниями. STORE не требует ZIP-WASM.

**Сервер.** Фактическая привязка 127.0.0.1; строгие Host и GET/HEAD; MIME/CSP/nosniff;
URL-кодирование, traversal, symlink и запрет неразрешённых файлов. Проверены
отсутствие dist/Node/npm и диагностическое сообщение для неподдерживаемых версий
Node (версии моделируются только в изолированном тесте проверки диапазона).
Занятый порт не меняет чужой сервер. Готовая поставка запускается без node_modules
из папки с пробелами и кириллицей, с другой рабочей директорией; SIGINT освобождает
порт, повторный запуск успешен. Ошибка xdg-open не останавливает сервер. Долгоживущий
тестовый процесс открытия браузера завершается при остановке Node-сервера.

**Сеть.** Чистый браузерный контекст, пустой кэш. Страница может обращаться только
к точному http://127.0.0.1:8089. Перед исполнением каждого Worker по CDP включены
Network и блокировка внешнего HTTP(S). Контроль рекурсивен, включая вложенный
blob-Worker libheif. Первые JPEG и PNG, скачивание, ZIP, очистка и новый запуск
прошли. Запросы — только статические ресурсы и blob URL, GET без тела; имена
фотографий не попадают в запросы. Попыток внешних соединений приложения не найдено.
После обработки активных Worker не осталось. localStorage/sessionStorage,
IndexedDB, Cache Storage и Service Worker пусты.

**Интерфейс.** Настройки блокируются во время конвертации, PNG скрывает качество,
показаны параметры старых результатов, ошибки выводятся текстом, HTML в имени
не исполняется. При ширине 390 px длинное русское имя не создаёт горизонтальный
скролл. Основные поля подписаны, есть клавиатурные элементы и aria-live.

## Техническое решение по CSP

До UI-проработки проведён отдельный production-пробник. heic-to/next завершился
EvalError из-за new Function в embind при script-src 'self'. Вариант heic-to/csp,
bitmap API + OffscreenCanvas в Worker, прошёл JPEG/PNG и тесты ориентации/alpha.
unsafe-eval и wasm-unsafe-eval не добавлялись. Это обоснованная замена импорта,
а не скрытый переход на сервер или внешний сервис.

## Непроверенные границы

- Windows 10/11, setup.bat/start.bat на настоящей Windows и Chrome/Edge там.
- macOS, start.command на macOS, Safari и Firefox.
- Физическое отключение сетевого адаптера: вместо этого применена описанная
  блокировка внешней сети приложения и обоих уровней Worker в чистом профиле.
- Максимальные реальные 50 Мп, 150 МиБ оригиналов и 200 МиБ результатов;
  проверки пределов выполнялись на контролируемых данных/unit, без стресс-приёмки.
- Все камеры, HDR/10–12 бит/ICC, EXIF-only ориентации, спорные HEIF-контейнеры,
  Live Photo, видео и анимация. Для контейнера без primary upstream берёт первое
  доступное изображение; этот fallback не объявлен универсально корректным.

Лимит пикселей в публичном bitmap API проверяется после декодирования. Поэтому
размеры файлов и тайм-аут не гарантируют отсутствие пика памяти до проверки.
Работа сервера на Linux и подготовленные Windows-скрипты не заменяют приёмку
целевой Windows-платформы.
